# نموذج الموظف والحساب

يُعامل **ملف الموظف** بوصفه السجل المرجعي للهوية والصلاحية داخل مخزن REVERSE TECH. أما حساب المستخدم فهو وسيلة دخول ذلك الموظف فقط، ولا يُنشئ حق دخول للمخزن بمفرده.

| قاعدة العمل | التطبيق |
|---|---|
| موظف واحد لكل حساب | يستخدم `employeeProfiles.userId` كارتباط فريد بين الموظف والحساب. |
| حساب واحد لكل موظف | لا يمكن ربط ملف موظف بحساب ثانٍ، ولا يُستبدل الربط من دون إجراء إداري صريح. |
| اسم العرض | يؤخذ من `employeeProfiles.fullName`، وليس من الاسم الذي يدخله المستخدم وقت التسجيل. |
| صلاحية المخزن | تؤخذ من `employeeProfiles.warehouseRole`؛ الأدمن يبقى أدمنًا، وبقية الأدوار تدخل بصفة مستخدم. |
| أهلية التسجيل | لا يُسمح بالدخول إلى التطبيق إلا عندما يطابق بريد حساب Supabase ملف موظف نشطًا ومسبق الإنشاء. |
| الحسابات غير المطابقة | قد تُنشأ جلسة خارجية لدى مزود المصادقة، لكنها لا تحصل على مستخدم داخلي أو صلاحية للولوج إلى المخزن. |

## مسار التسجيل

ينشئ الأدمن ملف الموظف أولًا، شاملاً الاسم المعروض والبريد الوظيفي أو البريد المعتمد وكود الموظف والقسم ودور المخزن. يستخدم الموظف البريد نفسه وكلمة مرور يختارها عند إنشاء الحساب. عند أول جلسة صحيحة، يربط النظام الحساب بملف الموظف ويستخدم اسم الملف وصلاحيته تلقائيًا.

> لا تظهر قائمة أسماء الموظفين على شاشة التسجيل العامة، ولا يُتاح اختيار دور الأدمن أو المستخدم من المستخدم نفسه. يمنع ذلك انتحال هوية موظف آخر أو طلب صلاحية أعلى من الدور الذي حدده الأدمن.

## ترحيل الحسابات الحالية

تُربط الحسابات الحالية تلقائيًا فقط عند تطابق بريد الحساب مع بريد ملف موظف نشط لم يُربط بحساب آخر. لا يُخمن النظام البريد أو الاسم، وتبقى الحالات غير المطابقة بحاجة إلى ربط أدمن صريح أو تحديث بريد الموظف.
